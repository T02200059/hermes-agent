## ⚠️ Gateway Daemon / Service Manager 注意事项

> 以下为 macOS launchd + Hermes Gateway 优雅退出踩坑记录。systemd 环境有类似问题，但 gateway 代码已针对 systemd 做了适配（`RestartForceExitStatus=75`）。

### ExitTimeOut 必须 ≥ restart_drain_timeout

**问题**：macOS launchd 的 `ExitTimeOut` 默认 **5 秒**，但 Hermes Gateway 的 `restart_drain_timeout` 配置为 **180 秒**（config.yaml）。当 gateway 收到 SIGTERM 时，需要最多 180 秒来 drain 活跃 agent（等待当前 turn 完成、标记 `resume_pending`、保存 session 状态）。launchd 5 秒后发 SIGKILL，gateway 被强杀，导致：
- session 状态未完整保存（`sessions.json` 可能是旧版本）
- `resume_pending` 标记可能未写入
- adapter 未正常断开（Feishu WebSocket 僵尸连接）
- 下次启动时 session 被 reset → 对话历史丢失

**修复**：在 `~/Library/LaunchAgents/ai.hermes.gateway.plist` 中添加：
```xml
<key>ExitTimeOut</key>
<integer>300</integer>
```
值应 ≥ `config.yaml` 中的 `agent.restart_drain_timeout`（当前 180s），留余量取 300s。

### 其他注意点

- **`--replace` 标志**：gateway 启动时会 SIGTERM 旧进程。如果旧进程正在 drain，需要 ExitTimeOut 给足时间。
- **`KeepAlive: true`**：launchd 会在 gateway 退出后自动重启。配合 `--replace` 使用，确保只有一个实例。
- **Crash loop**：如果 gateway 启动即 crash（如 import 错误），launchd 会反复重启。应在 plist 中考虑加 `ThrottleInterval` 限制重启频率。
- **systemd 对比**：gateway 代码对 systemd 有专门适配（exit code 75 + `RestartForceExitStatus=75`），但 launchd 没有等价机制，只能依赖 `KeepAlive` + 足够的 `ExitTimeOut`。
