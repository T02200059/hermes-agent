## 理由（短）

- 负担来自清单膨胀 + 神文件 + 测债，不是「owner 目录选错」。减负靠 **短名单 + 能力包 + 本四阶段节奏**。  
- 官方 profile / multiplex 是同用户同进程；node010 要跨 Linux 用户 → **部署与路由维持原舰队**，放在**最后一阶段**单独做。  
- 先非渠道底座 → 飞书核心（名缓存/卡/审批/i18n）→ 再叠小定制与杂项 → 最后多 profile，避免未有卡基建就铺体验、或过早动跨进程路由。
