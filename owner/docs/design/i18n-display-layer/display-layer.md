## 1. 一句话与边界

**做什么**：把「中文」从官方函数体里挪到展示边界。官方代码保持英文原文（与上游逐字节一致 → 不产生冲突块），中文由 `owner/i18n/display_filter.py` 在最后一次展示前整串替换。

**为什么值得做**：i18n 是 `MOD` hunk 的头号来源。owner 在官方文件里嵌了 958 处 `t()` 调用（48 个文件），其中 644 处使用的键上游没有——这 644 处是纯粹的 owner 改动，每一次 sync 都要重解一遍，本期 433 个冲突块里约 70% 出自这里。

**非目标（明确不做）**：
- **不动上游已用 `t()` 的位置**。上游自带的 276 处 `t()` 是官方机制，owner 只负责在 `locales/zh.yaml` 补键（catalog 是追加式写入，几乎不冲突）。对这些位置做展示层过滤属于重复劳动且有风险。
- **不做子串/正则文本替换**。见第 4 节。
- **不覆盖非展示面**：日志、traceback、工具返回值、被逻辑匹配的字符串一律保持英文。这是 T1-1 的直接教训。
- **不改 `agent/i18n.py`**：上游模块零改动，`t()` 语义与 catalog 格式保持不变。

## 3. 迁移等价性（先证明，再动手）

迁移**只有在**「过滤器作用于英文原文的结果 == `t(key)` 的结果」时才成立。这条前提在动手前已量化（`owner/i18n/tests/test_migration_equivalence.py`，对工作清单逐条断言）：

| 项 | 结果 |
|---|---|
| owner 侧调用点 | 644 |
| 等价 | **638（99.1%）** |
| 需人工处理：catalog 缺中文 | 1 |
| 需人工处理：歧义未消解 | 2 |
| 需人工处理：模板重叠/未命中 | 3 |
| 过滤表规模（zh） | 912 精确 + 684 模板 |
| 精确项往返 | 940/940 = **100.0%** |
| 模板项往返 | 683/685 = **99.7%** |

即：644 处里 638 处可以机械回退，剩 6 处需要人看。清单见 `owner/docs/i18n-display-layer-migration.md`。

### 3.1 收益边界：「纯包裹」占 219/644

回退 `t()` 只有在**该处 owner 的唯一改动就是包 `t()`** 时才能让代码恢复上游字节、
冲突块归零。清单按「该键的英文原文是否逐字作为字符串常量出现在上游官方文件中」
（AST 精确提取）判定：

| 类型 | 数量 | 回退的效果 |
|---|---|---|
| **纯包裹**（英文原文见于上游） | **219** | 与上游逐字节一致 → **冲突块归零** |
| 自造文案（上游无此句） | 425 | 官方代码不再携带 `t()`，但仍与上游不同 → 不消冲突 |

即 T1-4 的**冲突消除收益约为 219 块**。425 条自造文案的回退仍有价值（缩小后续
sync 的改动面、统一走展示层），但不是本期 P0 的收益来源，可后置。

219 是保守下界：AST 精确匹配要求英文原文本身是上游的独立字符串常量；若上游把
owner 所包的那段文案作为更长字面量的一部分（子串情形），回退同样能消除该行冲突，
但不会被这条判据计入（子串口径的上界为 251）。

## 4. 安全约束（源自 T1-1）

T1-1 的根因是「把展示用译文写进机器可读的返回值，而消费方按英文正则匹配该值」——同一个字符串既被展示又被逻辑匹配时，翻译会击穿逻辑（实测 `HERMES_LANGUAGE=zh` 下 90 条破坏命令模式有 54 条失去排除资格）。

因此过滤器有明确边界：

1. **只在真正的展示边界调用**（把消息发出去之前），不得用于返回值、状态字段、或被逻辑匹配的字符串。过滤器本身只做精确匹配、绝不猜测语义；「只喂展示面」是调用方的责任。
2. **只做整串匹配**，不做子串替换——避免改坏消息里嵌着的命令、路径、标识符。已有用例断言：把某条 catalog 原文嵌进 `sudo … /etc/hosts` 后不得被替换。
3. 未命中原样返回（优雅降级，不漏字不串码）。
4. 含 `{placeholder}` 的模板走模板匹配：静态片段必须完整匹配，占位符捕获内容**原样保留**，只替换静态片段。
   - **静态骨架总长 < 3 字符的模板直接拒绝**：否则正则会退化成「匹配任意字符串」。现网恰好命中 1 例（`approval.scan_summary`，英文骨架仅 `": "`），已用用例钉死该数量。
   - 不开 `re.DOTALL`，`.` 不跨行，避免模板吞掉整段多行输出。
   - 译文引入原文没有的占位符 → 拒绝该条。
   - **模板按静态骨架长度降序**：模板之间存在重叠匹配（实测 89 个键的填充串会被多个模板命中），必须让更具体的模板优先，否则会出现「用 A 句的译文渲染 B 句」。
5. 同一英文原文对应多个不同中文键时**默认不翻译**（现网 2 处），并记入 `unresolved_texts()`；确需消解时在 `_AMBIGUOUS_OVERRIDES` 显式指定（现网 2 例已指定）。
6. 目标语言为 `en` 时恒等，零开销短路。

另有一条 **AST 断言**（`test_display_filter.py`）：`tools/approval.py` 与 `owner/semantic_audit/detector.py` 不得导入本过滤器——防止展示层翻译渗进判定层，重现 T1-1。

## 5. 挂点选型

沿用仓库既有模式（见 `owner/display_overrides.py` 的先例）：**官方代码只留薄 `# [owner]` 胶水，实现全在 `owner/`**。

- 过滤器本身对「从哪调用」不敏感，只要求调用点位于真正的展示边界。
- 官方文件里原本的 `t("key")` 回退为英文原文后，该处与上游逐字节一致，冲突块归零。
- 展示边界的接入点按渠道逐个确定（gateway 各平台 adapter / CLI 输出）。**每个接入点必须配一条端到端冒烟断言**——因为「门存在但未生效」比「门不存在」更危险（T4-1/T4-2 的既定原则）。
